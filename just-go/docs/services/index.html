01 / SERVICE MODEL

The label determines the behavior.

A station field is not simply “available.” It belongs to one of four classes, and the app must preserve that class from display through network behavior.

APP CONTENTIncluded data

Catalog metadata, 53 route-picker baselines, and 14 offline city packs shipped with the build.

 ON-DEVICE FETCHStation information

1,598 reviewed stations. Four operators are read from the rider’s own device and cached device-only.

 USER ACTIONOfficial-resource links

770 operator hyperlinks across 698 unique targets that open only when the rider taps them.

 ONLINE REQUESTLive Hong Kong arrivals

Current results requested from the government transport API for referenced stations.
No category promotion

An official-resource URL is not an included page or file. A fetched station snapshot is operator content on one device, not a Just-Go dataset. A live-arrival reference is not an offline timetable. Missing data remains missing.

02 / INCLUDED DATA

Files available as app content.

Included means the data or media is delivered with the app build and may be counted as offline content. It does not require opening a provider webpage.

03 / STATION INFORMATION

Read from the operator, kept on one device.

Station Detail shows three categories for 1,598 reviewed stations. Beijing, Shanghai, Guangzhou, and Hangzhou content is licensed for external linking only, so the rider’s device fetches it directly and Just-Go redistributes it to nobody.

TRIGGERThe rider opens a station’s detail page. Nothing is requested in the background.
REQUESTThe station’s reviewed opaque operator identifier, over an ephemeral session with a 1 MB response cap.
VALIDATIONThe returned station identity is checked against the requested one before any row is rendered.
STORAGEThe last good snapshot is written to a schema-versioned, backup-excluded cache directory on that device only.
OFFLINEAn availability failure—offline, 429, 5xx, or timeout—serves the stored snapshot labeled “saved on this device · updated X ago.”
NEVER CACHEDA contract or identity violation is never served from the cache. A wrong answer does not become a durable one.
DELETIONSettings → Clear Cache wipes every snapshot, as does the data-rights epoch cleanup.
Fetched data never reaches route feasibility

Online station information informs the station page and route card only. A validator guard keeps it out of route feasibility, planning, and confidence scoring, so a route’s viability never depends on whether an operator answered.

04 / EXTERNAL REFERENCES

A link is not a local asset.

The separate directory contains 770 hyperlink records: 275 Maps, 447 Travel, 6 Accessibility, and 42 Help, resolving to 698 unique targets.

  • Just-Go opens an operator page or file only after the rider taps its link.
  • Just-Go does not bundle, prefetch, or redistribute those destinations. Pages open in a non-persistent WebKit session; documents use memory-only native viewers capped at 50 MB.
  • External pages and files are not counted as offline content.
  • Hong Kong links to 1 MTR System Map, 98 Location Maps, 98 Station Layouts, and 14 Light Rail Street Maps.
  • After opening, the destination provider and the rider’s browser or system web view handle the connection under their own terms and privacy practices.
  • A broken or changed external page does not become an included fallback copy.

05 / LIVE ARRIVALS

Hong Kong requires a live request.

All 162 matched Hong Kong stations have live-arrival references. When the rider asks to view current arrivals, Just-Go contacts the DATA.GOV.HK government transport API.

06 / PLACE TAGS

Tags for stations and for anywhere else.

Tags fill the active planner field in one tap. Home and Work are single-slot special tags—saving a new Home takes over the slot, matching the iOS convention—and custom tags are unlimited.

  • Any map place can be tagged, not only a station. A place tag stores its address and fills the planner exactly as a station tag does.
  • Tags are added and managed from the station page, the map card, or Settings → Tags, which includes a search sheet covering both network stations and map places.
  • Records are stored locally. No account or synchronization service receives them.
  • Place tags are skipped by the station-repair pass, so a tagged café is never rewritten into a nearby station.

07 / MAPS & ROUTING

Surface routing is not indoor routing.

Place search, device location, walking approaches, and walking-step rerouting may use Apple frameworks and therefore may require a network connection. Route-picker baselines are included for 53 cities; 5 catalog-only cities do not have one. Transit previews draw the traveled segment of the selected OpenStreetMap-derived track geometry.

Current indoor boundary

Indoor navigation was removed rather than left dormant, and verified indoor transfer coverage is zero. Route-picker geometry and external maps do not establish an indoor path, platform, door, transfer, or verified step-free route. On a transfer, Go names the station and defers to station signs.
